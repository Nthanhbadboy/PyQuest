## Vấn đề đã xác minh bằng code, không suy đoán

`tools/design/export_village_kit.py::export()` gọi vô điều kiện

```python
baseline_source = ROOT / 'app/assets/images' / asset['baseline']
baseline.write_bytes(baseline_source.read_bytes())
```

nên sau khi PQC-002 thay thumbnail, chạy lại exporter sẽ chép **art mới** vào
`baseline/` và ghi `manifest.json` với `baseline_sha256` mới → mất hẳn bằng chứng
"trước khi redesign". Cùng lúc `tools/design/test_village_kit.py::test_baselines_unchanged`
so `sha(app/assets/images/thumb_x.webp)` với `baseline_sha256` → test chỉ còn đúng
chừng nào app chưa đổi art, tức nó *đo sai thứ mà tên nó tuyên bố*.

## Việc phải làm (đề xuất cụ thể, design có thể đổi cách)

1. Exporter: nếu `baseline/<id>.webp` đã tồn tại → **không ghi**; verify hash khớp
   `manifest.baseline_sha256` và in cảnh báo nếu lệch. Ghi đè chỉ khi có
   `--refresh-baseline` tường minh, và khi đó ghi thêm `baseline_recorded_at`,
   `baseline_commit` vào manifest.
2. Test: tách hai thứ đang bị gộp một:
   * `test_baselines_unchanged` → chỉ so `baseline/*` với `baseline_sha256` trong
     manifest (bất biến, không đọc `app/`).
   * `test_runtime_matches_approved_export` (mới) → so `sha(app/assets/images/<baseline>)`
     với `sha(exports/<id>_512.webp)` của asset có `runtime.approved == true`.
3. Manifest: thêm `runtime: {path, variant, approved: false}` cho mỗi asset; cờ
   `approved` do người dùng/design bật, **không phải** do code branch.
