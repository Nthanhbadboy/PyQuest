### D6 — raw storage còn phân biệt được; không cần hỏi người dùng chọn mất dữ liệu

**Bác nhận định không đọc được từ storage.** Getter `lang` có lossy fallback, nhưng
`SettingsService.load()` lấy map từ repository; `raw(String key)` vẫn có ở dòng46.
`SettingsRepository.all()` trả đúng map key/value từ DB. Tại reviewed SHA, git grep
`ui_lang` trong app chỉ ra getter/setter, không có đường seed key mặc định.

Migration đọc **raw**, không đọc getter đã coalesced:

| Trạng thái | Kết quả |
|---|---|
| New preference key hợp lệ | Dùng nó, kể cả system; không cho key cũ ghi đè |
| New key có nhưng hỏng/unsupported | System; không khôi phục lựa chọn cũ ngoài ý muốn |
| Chưa có new key, raw `ui_lang=vi/en` | Giữ explicit vi/en |
| Chưa có cả hai key, hoặc legacy value hỏng | System |

Không suy `fromCode(null)==vi` thành người dùng chọn vi. Có thể dùng key mới
`ui_locale_preference` với giá trị `system|vi|en`, migration idempotent, không persist
locale resolve tự động. Test real repository/settings fixtures kể cả load lần hai,
new system + legacy vi, và lỗi write không báo lưu thành công. Không cần đổi DB schema
chỉ để lưu key/value mới. Nếu tìm thấy code seed ở phiên bản khác, đưa SHA/bằng chứng,
không giả định mọi DB cũ đều đã explicit vi.

### D7 — preference riêng; BCP47 ở ranh giới, enum tương thích ở adapter
